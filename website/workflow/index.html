FIVE-STAGE DECISION LOOP

五阶段 PM 决策工作流

这套流程解决一个具体问题：团队在没有确认问题、证据和取舍时，就把需求推进到设计或研发，最终造成返工。

01问题说明
02证据日志
03决策记录
04轻量 PRD
05结果复盘

每个阶段只回答一个核心问题

阶段 核心问题 主产物 通过条件
01 接收 用户为什么需要改变？ 问题说明 不是直接接受解决方案
02 证据 哪些信息可以验证？ 证据日志 标签、矛盾和缺口清楚
03 决策 为什么选择这条路径？ 决策记录 替代方案和取舍明确
04 PRD 最小可执行范围是什么？ 轻量 PRD 设计研发可以执行
05 验证 是否产生预期变化？ 结果复盘 有继续、调整或停止结论

实际使用顺序

  1. 修改 workflow/state.json 中的当前 initiative。
  2. 打开对应的 Skill 文件，确认输入和通过条件。
  3. 复制 templates/ 中的模板完成主产物。
  4. 每次证据或决策变化，在 workflow/log.md 增加记录。
  5. 不满足通过条件时，不进入下一阶段。

证据等级

标签 含义 可以证明什么
FACT 可核验的数据、文档或行为 支持具体的事实判断
ASSUMPTION 当前推断 只能用于提出待验证假设
SIMULATED AI 角色扮演或虚构访谈 只能用于练习和发现缺口
诚信边界： 模拟证据必须同时标记为未经验证，不能用于证明真实需求、市场规模或业务收益。

工作流完整，但执行深度不必相同

  • 明确且低风险的小优化：问题说明、简要决策和验收标准即可。
  • 常规需求：完整走过证据、决策和轻量 PRD。
  • 高影响或高不确定性需求：增加真实访谈、数据分析和原型验证。

工作流的作用是让分析深度与风险匹配，而不是把每个需求都变成大型项目。
